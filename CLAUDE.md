# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. Use plain language, short sentences, and avoid dense or overly compressed phrasing.

## What this is

`agent-team` — a minimal [Agent Client Protocol](https://agentclientprotocol.com) **client** in TypeScript and ES modules. Zero runtime dependencies, Node ≥24, `"type": "module"`, no build step; `biome` formats and lints (`npm run fmt:check`), `node:test` covers pure functions and wire behaviour (`npm run test`).

The inversion that governs every design choice: **this code is the client, the coding harness is the agent.** We spawn the harness as a subprocess, own the workspace, serve its filesystem requests, and decide its permissions. Harnesses (opencode, gemini, copilot, …) authenticate themselves — this client never touches a key.

## Commands

```bash
npm run check               # type-check: tsc --noEmit, guarded on .ts discovery (protocol/ is typed since M1a-2)
npm run fmt                 # biome format + lint autofix (biome check --write .)
npm run fmt:check           # biome format + lint check (biome check .)
npm run test                # node:test: pure functions, plus wire behaviour in protocol/
npm run knip                # dead-code / unused-export check, both dev and --production
npm run selftest            # end-to-end against mock-agent.mjs, --mode auto (writes ACP_TEST.md)
npm run test:harness        # opt-in: the real harnesses, local only (needs credentials, spends tokens)
node run.ts "self test" --cmd "node mock-agent.mjs" --mode safe   # same run, write refused
node run.ts "<prompt>" [--agent opencode|omp|pi|claude|gemini|copilot] [--cmd "<cmd>"] [--cwd dir] [--mode ask|safe|auto] [--verbose] [--quiet]
node run.ts --file <run.json>   # N tasks from a run file (tasks.json is the worked example)
```

`node:test` covers pure functions in `core/` and `protocol/`, and — per the 2026-08-31 amendment in `docs/STORIES.md` (M1a-1) — behaviour whose subject *is* the wire, which a pure function cannot express. Suites live in a `tests/` folder beside their sources — `core/tests/`, `protocol/tests/`, and `tests/` at the root for `run.ts` and `render.ts`; `npm run test` runs them all. `protocol/tests/agent.test.ts` is subprocess-driven: it spawns **fake** harnesses — `node -e "…"` scripts written inline in the test file, plus `mock-agent.mjs` where a scenario already covers the case — over real stdio, to prove what does and does not reach the subprocess. No real harness binary is launched by `npm run test`, which is why CI needs no credentials; that suite is `integration/` below. `mock-agent.mjs` is the end-to-end test harness: it implements the agent side of the protocol and drives every client code path (streaming, `fs/read_text_file`, `session/request_permission`, `fs/write_text_file`). **Verify changes to `protocol/agent.ts` against it before touching a real harness** — it needs nothing installed. Extend `mock-agent.mjs` when adding client capabilities so the new path is exercisable offline. Its non-compliant fixtures are selected by `--scenario <name>` on argv (M1b-5) — `refuse`, `silent-session`, and one per `core/result.ts` cross-check — never by a keyword in the prompt, because `silent-session` fires during the handshake, before any prompt exists. An unknown name exits 2 rather than running the default path. `hostile-agent.mjs` (M1b-6) is its opposite and lives beside it: one attack per `--scenario` — path escape, absolute path, symlink escape, a write with no permission request, an allow-only permission menu followed by two writes, a non-JSON line, a line past the length cap, and a method we do not implement. It has **no default scenario** (a bare run exits 2), because a hostile agent with no attack selected is a worse mock, and `protocol/tests/hostile.test.ts` drives every one of them. Every scenario ends its turn normally after the attack: the story's *Done when* is refused **and the run continues**, so a scenario that killed the turn would prove only half of it. `ACP_TEST.md` in the repo root is selftest output, not source; deleting it is safe.

`tests/cli.test.ts` drives `run.ts` as a real subprocess and needs **no harness** — argv validation, the notice/`--quiet` split, and the run-file path's concurrency all run against `mock-agent.mjs` or fail before a subprocess starts, so it runs in CI on every push. It shares `runCli` (which wraps `spawnCli`), the temp-dir helper, and `MOCK_AGENT` with the suite below rather than copying them.

`integration/*.itest.ts` is the **real-harness** suite (`npm run test:harness`) — it drives `run.ts` as a subprocess against the actual `opencode`, `claude-agent-acp` and `copilot` binaries, so it needs credentials and spends tokens. `node --test` does not discover the `.itest.ts` suffix, which is the only thing keeping it out of CI; do not rename the files. A harness that is not installed **skips** rather than fails, so a partial machine stays green. Assert on what the client controls — an exit code, our own notice lines — and **never on the agent's prose**, which changes every run. A file on disk is never enough on its own — an empty workspace is also what a harness that simply obeyed its negotiated plan mode leaves behind — so assert the client's own `_client_permission` refusal line first, then the directory. Measured 2026-09-04, three runs each: copilot requests an `edit` and `safePolicy` denies it; **claude never gets that far**, asking instead to leave plan mode (`switch_mode`), which `safePolicy` also denies — so `safe` there is an interlock, negotiate plan then refuse the way back out. opencode denies nothing because it asks nothing, so plan mode is an instruction the model may ignore — it wrote the file on one run out of several, which is why its tests assert the negotiation and the notice instead of the disk. `--mode ask` is untestable here at all: a test runner has no TTY, so it re-resolves to `safe` before the first notice is composed.

`--mode ask` requires a TTY and degrades to `safe` otherwise, so piped/CI invocations never block on a prompt.

The containment notice `warningsFor` prints, plus the not-negotiated line, are **never suppressed by `--quiet`** (#13): `safe` keeps its name only because that notice carries the caveat. `warningsFor` returns `{kind, text, onceKey?}` so the call site can make that split — `containment` always prints, `unverified` and `version` are advisory and `--quiet` drops them. A third line joins them under `--quiet`: M1b-4's cross-check disagreements, printed by a bus subscriber `run.ts` installs **only** in the quiet path, because a quiet run has no task card to carry them. `onceKey` is the other half of that rule — a line that names a property of the *harness* rather than of one task prints once per run, which is why N opencode tasks say "never asks permission" once instead of N times.

**Harness spawn failures surface as opaque JSON-RPC errors** — typically `Internal error (code -32603)` on `session/new`, with the real message only on the harness's stderr under `--verbose`. Reach for `--verbose` first — or, for a `--file` run, read `.agent-team/runs/<runId>/<taskId>.stderr.log`, which M1b-7 writes for every task with no flag asked for. The `--agent claude` case is the one to know: older adapters refused to start a nested session when they saw the markers a parent Claude Code session leaves in the environment, and `AcpAgent` passes its `env` through to the subprocess. The `claude` entry scrubs those markers (`CLAUDECODE`, `CLAUDE_CODE_SSE_PORT`, `CLAUDE_CODE_ENTRYPOINT`) via the registry `env` field (`protocol/registry.ts`), so no `env -u ...` prefix is needed. Adapter 0.49.0 no longer refuses, so the scrub is regression insurance rather than a fix for a live failure. The deprecated `claude-code-acp` adapter is no longer in the registry.

## Architecture

One direction of dependency: `run.ts` → `core/` → `protocol/agent.ts` + `protocol/registry.ts` + `render.ts`, typed by `protocol/types.ts`. **`core/` may import `protocol/`; never the reverse** — that is why `AcpAgent`'s default policy refuses everything rather than being `safePolicy`.

- **`protocol/agent.ts`** — everything protocol. An inbound stdout line longer than `MAX_LINE_LENGTH` (32 MiB, M1b-6) is dropped with a line on stderr that `--quiet` does not suppress, and the turn carries on; `readline` has already buffered it by then, so that refuses the payload rather than bounding the memory — a real bound means a manual chunk scanner, marked `ponytail:` at the constant. `AcpAgent` owns one subprocess: spawn, newline-delimited JSON-RPC over stdio, `initialize` handshake (hard-fails on `protocolVersion` mismatch), `session/new`, `session/prompt`, `session/cancel`. It handles exactly three inbound requests — `fs/read_text_file`, `fs/write_text_file`, `session/request_permission` — and one notification, `session/update`, which it forwards to `onEvent`.
- **`protocol/registry.ts`** — the entire adapter layer (M1a-4, was `agents.mjs`). A map of agent id → `{launch, measured?}`. **The split is load-bearing.** `launch` is `{command, args, env?}` — a recipe we choose. `measured` is a lab report: `shell`, `argvChannel`, `asksPermission`, `modeMap`, `usage`, `meta?` and `measuredOn`, every field a claim about one *build*. `omp`, `pi` and `gemini` were never run here, so they carry no `measured` — its **absence is the only marker of an unverified harness**, and `warningsFor` reads that absence as the least contained harness we did measure. Supporting a new harness is still one entry, not an integration. `env` is `{unset?, set?}`, applied by `resolveEnv`, which also strips `AGENT_TEAM_*` from every harness's environment unconditionally (M2-8's shared secret must never reach a subprocess). `resolveEnv` returns `process.env` **by identity** when there is nothing to do, so quirk-free harnesses don't each get a copy. `resolveAgent` also parses `--cmd` strings and derives a readable label (`node mock-agent.mjs` → `mock-agent`); a `--cmd` spec has no `measured` half, so it warns as unverified.
- **`render.ts`** — terminal formatting for `session/update`. Pure presentation; no protocol logic.
- **`core/run.ts`** — the pool and the status arithmetic (M1b-2). `statusFor` keys on the **triple** — `stopReason`, did we cancel, did the watchdog fire — because M0-4 measured copilot answering `end_turn` for a turn it had itself cancelled; our own record wins and `stopReason` is consulted only where the two agree. `runStatus` takes the worst task status, ordered `done < warned < cancelled < skipped < timed_out < failed`. **The roll-up is duration and turn count only** — `usage` stays on the task that produced it, tagged, never summed, because copilot counts cumulatively where opencode counts per turn. `taskCwd` is gone — M1b-3 replaced it with `core/worktree.ts`, acquired before the executor and released after, and teardown never changes a task's verdict. `runRun`'s third parameter is an injected executor, the only way to observe "never more than `maxConcurrency` live" without counting real subprocesses.
- **`core/worktree.ts`** — one `git worktree` per task at `.agent-team/wt/<runId>/<taskId>`, on branch `agent-team/<runId>/<taskId>` (M1b-3). `openWorktrees` preflights **once per run**, not per task: `.agent-team/` tracked or unignored, or a dirty tree, **throw** — the message carries the fix, and the preflight never edits `.gitignore` itself, because appending dirties the very tree it then refuses on. A cwd that *cannot* carry worktrees — not a repo, or no commit to branch from — **falls back** to the shared cwd with a notice instead, so the CLI's own suite keeps working in plain `mkdtemp` directories; that notice is containment-shaped and survives `--quiet`. **The tracked/unignored refusals run before the no-commit fallback** (M1b-7): `core/run.ts` writes `.agent-team/runs/` whichever way the preflight ends, so a fresh `git init` with no `.gitignore` entry throws rather than falling through and creating state that would be committed by accident. `release` is keyed on `TaskStatus`: `done`/`warned` commit the work and remove the checkout, everything below keeps it uncommitted for reading. A worktree that is **untouched** (no diff, HEAD still at the base sha) has its checkout removed; for a non-releasing status — the shape a harness that never started takes — the branch is rolled back too, while a `done`/`warned` task with an empty diff leaves its branch at the base ref without an empty commit. Three things `#85`'s review found, each with a test that is red without its fix: the dirty check is `--untracked-files=all`, never a bare `--porcelain`, which `status.showUntrackedFiles=no` silently empties — a task whose whole output was new files read as untouched and was removed with the work in it; `release` verifies the checkout is still on the task branch and **keeps it with a warning** when an agent moved HEAD, rather than committing onto a ref the run does not track; and a `--cwd` naming a subdirectory is re-entered at the *same* subdirectory inside the worktree, because returning the checkout root would widen `#guardPath` from the requested subtree to the whole repository. That prefix is `relative()` over **realpath'd** root and cwd: `--show-toplevel` resolves symlinks and `--cwd` does not, and subtracting one from the other produced a `..`-prefix that put one task inside another task's checkout. A containment check on the joined path backs it up. `kill -9` mid-spawn can still orphan one; that is M2-5's sweep. `openWorktrees` also returns the `root` it settled on, because M1b-7's per-task stderr logs live beside the worktrees under the same `.agent-team/` — in the no-repository fallback that root is the cwd, so a run outside a repository still leaves the logs — but a cwd that does not exist is never created for a log, since `mkdir -p` would turn a typo'd `--cwd` into a real empty workspace.
- **`core/result.ts`** — the result contract (M1b-4). Three pure pieces: `RESULT_PREAMBLE`, appended to **every** prompt on both paths; `extractResult`, which takes the **last** `<task-result>` block in the message and returns `null` if the wrapper is absent or any of status/summary/details is blank after trimming (a missing *optional* field is `undefined`, never a rejection); and `crossCheck`, which compares the block against the task's changed paths and the permission count. Those paths come from `changedPaths` (`core/worktree.ts`), which reads `git status --porcelain -z --untracked-files=all`: **`-z` is load-bearing**, because without it git C-quotes unusual paths and writes a rename as `old -> new`, which needs a parser whose bugs #88 found. `crossCheck` is given the paths only when the task had a **worktree of its own** — in the shared-cwd fallback one task's files are in every other task's `git status`, and a task that touched nothing was told it had changed the tree without asking (measured 2026-09-08). **There is no re-ask** — `prompt()` throws on a second call (#62 R5), so the preamble lands first time or the task carries `noResultBlock` and a summary synthesised from the tail of the prose, flagged as ours. Warnings are never fatal: `runOne` promotes `done` to `warned`, publishes each disagreement on the run bus as `_client_result_warning`, and touches nothing below it. `diff: undefined` is *unknown*, not *empty*, so a run outside a repository skips every tree-shaped check rather than warning on all of them; `policyNeverFired` does not fire where the registry already says `asksPermission: false`, because `warningsFor` marks that containment line with `onceKey` and the run prints it once per run.
- **`schema/run.schema.json`** — an authoring aid an editor reads. **Never a second validator**: `validateRun` cannot be replaced by a schema that fills no defaults, reaches no registry and spots no duplicate id, and checking one at runtime would cost a dependency. One test asserts its property names equal `RUN_KEYS` and `TASK_KEYS`, which is the only thing keeping the copy honest.
- **`run.ts`** — single-agent CLI, hand-rolled arg parsing, SIGINT → `session/cancel` then 2s grace before kill. `--file <run.json>` is the other half: N tasks through `core/run.ts`, prose buffered per task, milestones live. `--agent`, `--cmd` and `--mode` are **refused** alongside `--file`, because the run file already answered those per task; and `ask` in a run file survives for **exactly one asker** — `makeAskPolicy` owns a single readline over one stdin, so two tasks prompting at once would interleave two questions and mis-attribute an answer. One asker plus a TTY keeps `ask`; anything else re-resolves every asking task as `safe`. M2-3's pending-decision queue is what lifts the limit to N, which is why `core/run.ts` takes the decider as `RunOptions.askPolicy` and never builds one.

### Two client invariants worth preserving

**Permission decisions depend on state carried across messages.** `session/request_permission` may arrive with only a `toolCallId`. Title and kind were announced earlier in the `tool_call` notification, so `AcpAgent` maintains a `toolCallId → {title, kind, rawInput}` map. Break that bookkeeping and every policy decision goes blind.

**The policy filters what a harness asks, and the one mutation it can perform through us — it is not a sandbox.** One file, `core/policy.ts`, applied identically to every harness. `safePolicy` allows only the `READ_ONLY_KINDS` set (`read`, `search`, `fetch`, `think`); `makeAskPolicy` auto-approves those and prompts per mutation; `auto` approves all — reach them through `policyFor(mode)`, which is the only map from a mode to a decider. What the filter can reach is per-harness — opencode never asks, and copilot's behaviour changed across builds — so per-harness containment lives in the registry, not in this sentence (`docs/M0-FINDINGS.md` §M0-1). `#guardPath` rejects any `fs/*` path outside the workspace root — comparing **realpaths** since M1b-6, because `resolve` is string arithmetic and a symlink inside the root pointing out of it used to read as in-root. Since M1b-6 `fs/write_text_file` also goes through the policy (`#guardWrite`) when no `session/request_permission` has already decided that exact path, which is the whole of "mutation without asking": without it `safe` refuses the *request* to edit and then performs the edit for any harness that skips the request and calls the file service directly. A write that follows an approved permission for the same path reuses that decision, so `ask` does not prompt twice for one edit. It is the only mutation the client can see on the wire; one made through the harness's own shell stays outside the policy's reach and is inferred afterwards by `policyNeverFired`. Both bound this client's own file service, not the agent, and no surveyed harness calls `fs/*` at all. Keep the two layers separate: policy is about intent, the path guard is unconditional and applies under `--mode auto` too.

**`safe` negotiates before it filters (M1a-5).** `negotiateSafeMode` sends `session/set_mode` with the registry's `measured.modeMap.safe` right after `session/new`, and that is the only half that reaches opencode, which never asks anything: measured, it wrote the file without negotiation and declined with it. Skipped for a harness with no `measured` half, because the ids would be a guess; skipped for `ask` and `auto`, because sending `auto`'s id would put claude into `bypassPermissions`. A skip or a failure prints a notice and continues — it never fails the run. The refusal arrives as agent prose, so this is defence in depth, not enforcement.

**Mode and `allowReadOutsideRoot` resolve in one place.** `resolvePolicy` settles `task > run > harness > default`. A mode above the entry's `maxMode` is a validation error naming both values, never a silent downgrade, and `safe` forces `allowReadOutsideRoot` to `false` however it was asked for. `ask` without a TTY re-resolves as `safe` rather than renaming itself, so `safe`'s own rules apply to what actually runs.

**A permission answer never guesses.** `pickOption` returns `null` when no option matches the decision, and the client answers the protocol's `cancelled` outcome. The old tail returned `options[0]`, which fails open — claude lists `allow_always` first, so a denial would have become a persisted grant (measured 2026-09-02, issue #13).

### Synthetic events

This layer emits four synthetic events of its own, not defined by the protocol: `_client_permission`, `_client_wrote_file` and `_client_cancel_requested` (M1a-3, #62 R4 — recorded at the moment `session/cancel` is sent, because copilot answers `end_turn` for a turn it cancelled, so our own record of having asked is the authoritative term for M1b-2), plus `_client_result_warning` (M1b-4, emitted by `core/run.ts` when a result cross-check disagrees). `render.ts` draws the first two; the third is capture-only; the fourth is printed by `run.ts`'s `--quiet` subscriber and is available to later bus consumers. The render switch has no `default`, so an unrendered variant is ignored rather than drawn incorrectly. Prefix any new synthetic event with `_client_` so it stays distinguishable from real `sessionUpdate` values.

## Deliberately unimplemented

Don't treat these as gaps to fill unless asked: `terminal/*` (we advertise `terminal: false` — and M0-3 measured that flipping it to `true` changes nothing: opencode, claude-agent-acp and copilot all run shell commands internally and never call `terminal/create`, so this is a recorded decision, not a gap. See `docs/M0-FINDINGS.md` §M0-3); `session/load` / resume (check `agent.agentCapabilities` before calling); elicitation, slash commands, session modes. Cancellation is best-effort.
